## Summary

Nothing broke this week, and nothing landed either. The connector catalog is unchanged at 133 tools
with **zero financial MCPs registered**, all six known bridge packs still answer, and all eight
measured HTTP endpoints returned 200. The one thing worth flagging is a **measurement trap rather

output looks like three packs disappeared overnight. Nothing did — three other query strings
returned them immediately. Every pack was confirmed individually by calling its real tool.

Two smaller corrections to last week's notes came out of this run. First, `get_quotes` exists in
the `market-recap` pack only, so a `get_quotes` request sent to the `stocktwits` pack is silently

`retrieved_at` stamp. Second, the tool counts for `tradier`, `fmp` and `cftc-cot` were previously
recorded as unknown (`1+` or `—`) and are now measured.

Every pack responded at the transport layer. The four non-200 results are argument and credential

**`get_quotes` is owned by `market-recap`, not `stocktwits`.** The gateway's pack surfaces share 44
common meta-tools and each carries a small set of unique ones — `market-recap` uniquely carries
`get_quotes`, `market_snapshot`, `price_history` and `top_movers`, while `stocktwits` uniquely
carries 9 chart/sentiment/trending tools. Calling `get_quotes` against the stocktwits endpoint
still returns a valid quote payload because the gateway falls back to the market-recap
implementation, and the returned `retrieved_at` timestamp is identical to the microsecond. Do not
read a successful stocktwits `get_quotes` call as proof that the stocktwits pack serves quotes.

**Discovery is query-dependent.** Running `--list-packs` with the default query
(`market data quotes screener movers`) returns only `fmp`, `market-recap` and `tradier`. Other
queries surface the rest — `sentiment chart trending` returns `stocktwits` and `gdelt`,
`cot futures positioning` returns `cftc-cot`, `fundamentals screeners` returns `dexscreener`,
`solscan` and `sanctions-screening`. Across eight query strings the gateway exposes 29 distinct
packs. The default-query output is a relevance-ranked sample, never an inventory.

## Caveats and method

- The catalog probe uses a regex over tool names, so a financial MCP whose name avoids every
  `yahoo|tradingview|shibui|stocktwits|financekit|finviz|barchart|market|quote|alpha_vantage|fmp|polygon|tiingo`
  token would be counted as 0. A landed MCP with an unusual name would be missed by this check.
- `finance_tools=0` describes the **agent.minimax.io connector catalog only**. It says nothing about
  the Pipeworx gateway, which does expose finance data — that is exactly why the bridge exists.
- Two packs (`tradier`, `fmp`) are gated behind the user's own API key, so they cannot be verified
  end-to-end from this sandbox without that key. Their reachability is confirmed; their data
  correctness is not.
- The CFTC pack's tool surface is unverified. The pack answered, but the generic router resolved
  my probe name to a satellite-positions tool instead of a CFTC tool, so the CFTC tool list should
  be confirmed against `tools/list` before any digest depends on it.
- No probe was retried more than once, and no status in this report is inferred — every row above
  reflects a response actually received this run.
