## Summary

**The watched item did not move: still zero financial MCPs.** No finance MCP landed, no stdio
server gained or lost a tool, no bridge pack stopped answering, and no HTTP endpoint went dark.

The one real delta is cosmetic: the connector catalog grew from **133 to 135 tools**, and the
growth is entirely in `connector__matrix__*` (13 → 15). GitHub (118) and email (2) are unchanged.

Two **probe-shape traps** were found this week, and both are worth keeping because each one fails
*silently* rather than loudly:

1. **`api.nasdaq.com/api/marketmovers` now rejects a non-browser User-Agent.** With a plain
   `mavis-health-check/1.0` UA, curl fails with **exit 92** (`HTTP/2 stream 1 was not closed
   cleanly: INTERNAL_ERROR`) — and **writes no output file at all**. A cron that checks
   "is the file there?" would read that as "Nasdaq returned no data" rather than "the probe
   failed". With a browser-like UA the same URL returns 200 with all three tables.
   `--http1.1` does not help (it times out instead). The fleet's own scripts already send browser
   UAs, so **no digest routine is affected** — but the §2a contract row for this endpoint does
   not state the UA requirement, and this routine's own prompt does not either.
2. **shibui table names must carry the `shibui.` schema prefix.** An unqualified
   `FROM stock_quotes` fails with *"Table with name stock_quotes does not exist! Did you mean
   shibui.stock_qu…"*. This is **not a service change** — the tool's own `inputSchema` has always
   said *"Requires shibui. table prefix and a LIMIT clause"*, and every SQL file in the repo
   (69 `shibui.`-prefixed references across 16 files) already uses the qualified form. It was
   this routine's probe that was wrong.

### The Nasdaq User-Agent trap (new finding)

| request | result |
|---|---|
| plain UA `mavis-health-check/1.0 (mavis@example.com)`, HTTP/2 | **curl exit 92** — `HTTP/2 stream 1 was not closed cleanly: INTERNAL_ERROR` — **no output file written** |
| plain UA, `--http1.1` | **curl exit 28** — timeout after 30 s, 0 bytes |
| plain UA + browser `Accept`/`Referer`, HTTP/2 | **curl exit 92** (headers are not the lever) |
| browser UA `Mozilla/5.0 … Chrome/124.0`, HTTP/2 | **200 OK**, 18 486 B, 3 tables |

The **User-Agent string** is the only lever that matters. Two consequences: (a) any script that
probes Nasdaq with a custom UA and then checks for the existence of an output file will silently
conclude "no data" instead of "probe failed"; (b) `RUNTIME-CONTRACT.md` §2a documents the UA
requirement for the Nasdaq **quote** API (§2b) but not for **market movers** (§2a). The repo's own
consumers — `tools/reversal_bullish.py`, `scripts/same_day_prints.py`, `scripts/premarket_pull.py`,
`scripts/premarket_universe.py` — all already send browser UAs, so the fleet is unaffected.

## Caveats and method

- The catalog probe uses a regex over tool names, so a financial MCP whose name avoids every
  `yahoo|tradingview|shibui|stocktwits|financekit|finviz|barchart|market|quote|alpha_vantage|fmp|polygon|tiingo`
  token would be counted as 0. A landed MCP with an unusual name would be missed by this check.
- `finance_tools=0` describes the **agent.minimax.io connector catalog only**. It says nothing about
  the Pipeworx gateway, which does expose finance data — that is exactly why the bridge exists.
- Two packs (`tradier`, `fmp`) are gated behind the user's own API key, so they cannot be verified
  end-to-end from this sandbox without that key. Their reachability is confirmed; their data
  correctness is not.
- The CFTC pack's tool surface is still unverified — the generic router resolved `get_positions` to
  a satellite-positions tool. The CFTC tool list should be confirmed against `tools/list` before any
  digest depends on it.
- The 18-vs-29 pack-discovery counts across weeks are **not** a trend line; the union depends
  entirely on the query strings used.
- No probe was retried more than once, and no status in this report is inferred — every row above
  reflects a response actually received this run. Two probes failed on their first attempt and were
  corrected on the single permitted retry (Nasdaq's UA, shibui's table prefix); both are described
  above.
