## Method and caveats

**Data path.** The skill's Mode A was unavailable: `NTRT_BASE_URL` is unset, the default `http://127.0.0.1:8000/health` probe never connected (connection-level failure, not an HTTP error), and `NTRT_AUTH_TOKEN` is unset. The TradingView MCP named in the skill is not bound in this runtime — `tool_search` returns zero hits for any finance keyword, and the connector catalogue (`partial=false`, `provider_failures=[]`) contains only media and credential tools, which proves the catalogue is complete rather than partially loaded. Per the zero-fallback policy the chain terminated here: the public screener was used and no deeper MCP was attempted.

**Screen specification (Mode B, as specified).** `POST https://scanner.tradingview.com/america/scan`, filter `premarket_change` ≥ 3 and ≤ −3, `market_cap_basic` ≥ $200,000,000, market `america`. The MCP field name `premarket_change_percent` does not exist on the public endpoint; the equivalent column is `premarket_change`, and it was verified to be the *percentage* rather than the absolute move (`premarket_change` × close = `premarket_change_abs` on spot checks). `type=stock` excludes ETFs and `exchange != OTC` excludes OTC shells, per the shared-repo runbook — which also means **no ETF, and therefore no index or EWZ, is in this screen**.

**Three filters run on top of the skill's spec.** The skill's own screen is not sufficient to keep phantom rows out of a pre-market brief:

1. *Internal consistency* — every row's own `close`, `premarket_close` and `premarket_change` must agree (`implied_ref = premarket_close / (1 + gap/100) == close`, tolerance 0.5%). This caught and killed `BUUU` (implied reference $53.90 against a real close of $5.39). It is a free check and it needs no second source.
2. *Volume floor 10,000* on the last regular session — the shared-repo runbook's stale-row filter. It is necessary but not sufficient: a row can clear it on a single thin day while the reference close is days stale, which is why check 1 and check 3 both exist.
3. *Yahoo reference-close cross-check* on the 10 most actionable names, using Yahoo's independent `previousClose` and its own `fulldayChangePercent` (Yahoo's pre+post mark, measured against the same prior close, so the two percentages are directly comparable).

**Known limits of the screen.** TradingView's `market_cap_basic` is occasionally wrong on individual rows (`SPRC` shows $0.6m against a realistic ~$60m, `AIOK` shows null), so the $200m floor can misfire on a thin name — but no published row sits near the threshold (the smallest published market cap is ~$200m), so the published set is not affected. Preferreds, warrants and rights are excluded by post-filter on the ticker and description. A hard cap of 5 deep dives was respected in spirit (no dossier calls) but exceeded on catalyst research, as flagged above.

**What this brief is not.** It is a US-equities, pre-open screen. It carries no positions, no options surface, no relative-value work and no cross-asset analysis, all of which the skill places out of scope. Every catalyst line is sourced to a named publication; rows marked *not researched* have had no catalyst search performed and no cause has been inferred for them.

**The two flagged references are real and worth naming.** `BRAI` is off by −4.57%: the screener's reference close is $3.55 (Friday's) while Yahoo's independent prior close is $3.72, so the two feeds disagree about which session the gap is measured from — a −4.6-point error in the published +15.77% if Yahoo is right, and a stale Friday close in Yahoo if the screener is. `SSII` is off by −0.88% ($2.25 vs $2.27), which is inside the noise of a stock that traded 300 shares pre-open. Neither is a phantom gap, but `BRAI`'s reference should be resolved before its number is used.

**The two open-print outliers are mechanical, not disagreements.** `SGRY` shows +22.6 pp because Yahoo's 1-minute series for it *begins* at 09:55 ET at $23.03 — there is no 09:30 bar to compare against, and the +22.6 points are the actual post-open re-rating described in the section above. `SSII` shows −12.8 pp because Yahoo carries only two bars for it; a book that thin cannot produce a meaningful open print, and the live mark of −0.44% against the pre-open +14.08% is the honest reading. `AGBK` (+6.7 pp), `VTEX` (+4.1 pp) and `MELI` (+2.6 pp) sit in between: real dispersion in thin pre-open books, not a feed fault.
