# Artifact contract — naming and shape rules for this repo

**Status:** active. **Applies to:** every artifact this fleet writes into
`karizaco/minimax-cloud-outputs`. **Last revised:** 2026-11-08.

The rules live here rather than only in a commit message because two of them were
learned the hard way: a basename containing `:` is illegal on Windows, and this repo is
checked out on Windows; and a dated directory that changes shape between runs makes a
glob silently wrong.

---

## Rule 1 — Artifact basenames must be Windows-safe

A `:` in a filename is illegal on Windows. It is legal on the Linux sandbox the crons
run in, so a routine can emit it happily and the failure only shows up on checkout.

**Rule.** A basename must not contain any of `< > : " | ? *`, must not end in a space
or a dot, and must not be a bare clock time.

**Why the clock-time clause.** The file was once called `reversal-bullish-3:55.md`
because 15:55 ET is when the scan runs. That name is a timestamp wearing a filename's
clothes: it is illegal on Windows, and it reads as a time rather than as an artifact.
The Windows-safe form is `reversal-bullish-3_55.md` — the same token with an
underscore — and the scan's time of day belongs in the artifact's body, where it
already appears (`screen started 2026-11-04T15:55:44-05:00`).

**The routine's *name* may still contain a colon.** The cron id
`04-reversal-bullish-3:55` is a task identifier, not a filename, and it is used as a
key in the scheduler and in `roster.json`. Do not rename it.

**Where this is already handled upstream.** The generator in
`karizaco/maxhermes-migration` writes `reversal-bullish-3_55.{md,csv}`, the skill
documents the Windows-safe basename, and `push_artifact.sh` sanitises illegal
basenames before a push. This rule exists in this repo so that a reader of an
artifact knows the naming is deliberate rather than accidental.

## Rule 2 — One filename shape per dated directory

Inside `daily-screens/<date>/`, files are named **without** the date prefix:

```
daily-screens/2026-11-06/focus.md
daily-screens/2026-11-06/focus.csv
daily-screens/2026-11-06/master.md
daily-screens/2026-11-06/tier-a.md
```

The date is already in the directory name. Repeating it inside the filename means a
consumer has to know two spellings for the same artifact, and one date in the archive
(`2026-10-23`) did exactly that — nine CSVs carried a `2026-10-23-` prefix while
every other date's did not. That was normalised on 2026-11-08.

**Rule.** No filename inside a dated directory starts with that directory's date.

## Rule 3 — A dated directory carries a `_manifest.json`

Because the file set genuinely varies between runs — a screen can be split into
components, or a run can produce nothing at all — a dated directory must carry a
`_manifest.json` stating:

- which file is the brief, and which are machine artifacts
- which screens are present, whether each has a matching `.csv`, and whether a
  screen is published as components instead of an aggregate
- the session lag, when the screen metrics describe an earlier session than the
  directory's date

`international-eod/<date>/_manifest.json` already works this way. `daily-screens/<date>/`
now does too, generated by `scripts/build_screen_manifest.py`.

## Rule 4 — A cross-repo reference keeps its own repo's spelling

A path that names a file in `karizaco/maxhermes-migration` is written with that
repo's spelling, because that is where the file lives. This repo's
`daily-screens/2026-10-27/reversal-bullish-3_55-CORRECTION.md` refers to
`cloud-prompts/cron-prompts/04-reversal-bullish-3:55.md` — the colon is correct there,
because the migration repo is hosted on a Linux sandbox and its prompt file was never
renamed. Do not "fix" it.

**Rule.** Renaming a file in one repo does not require rewriting references to a
*different* repo's file of the same name. The check in `scripts/check_artifacts.py`
excludes known external prefixes for exactly this reason.

## Rule 5 — A renamed artifact keeps its prose in step

When a basename changes, every in-text reference to it changes with it — in the
same commit. On 2026-11-08, commit `6569109` renamed 76 colon paths to underscores
but left the prose pointing at the old names; twenty in-repo references were still
broken when that commit landed, and were repaired separately.

**Rule.** A rename commit also updates the references, or is immediately followed by
one that does. `scripts/check_artifacts.py --mode links` finds the ones that were missed.

## Enforcement

```bash
python3 scripts/check_artifacts.py            # all three checks
python3 scripts/check_artifacts.py index      # does ARTIFACT-INDEX.md hold up?
python3 scripts/check_artifacts.py links      # do in-text references resolve?
python3 scripts/check_artifacts.py convention # are basenames safe and shapes consistent?
```

`index` and `convention` fail the run on a finding. `links` fails on any in-repo
reference that does not resolve; references to other repos and templated paths
(`{date}`, `<date>`) are counted and skipped rather than silently dropped.

The `convention` check also prints *shape differences* — a screen published without
its `.csv`, or split into components — as notes rather than failures, because those
are real properties of the data, not errors. They are now visible in
`_manifest.json` instead of only in a glob's silence.
